# img-vlm-extractor

이미지에서 값을 뽑는 것이 아니라, **뽑은 값을 믿어도 되는지 판정하는** 엔진입니다.
VLM 이 그럴듯한 오답을 쓰는 자리를 코드로 잡아내고, 못 믿을 것은 사람에게 넘깁니다.

> 진행 중인 프로젝트입니다. 지금은 **연구 단계**이고, 실험 결과가 나온 뒤에 본 코드로 옮깁니다.

---

## 무엇을 푸는가

OCR 은 이미지를 글자로 바꾸고, VLM 은 **질문에 답합니다.** 그래서 업체마다 양식이 다른
문서에서도 "총액이 어디인지" 를 지목할 수 있습니다. 대신 새로운 실패가 생깁니다.

```
영수증에 "35,000" 이 흐릿하게 찍혔다

OCR  →  "3S,OOO"      깨져서 나온다 → 이상한 게 눈에 띈다
VLM  →  "38,000"      자신 있게 그럴듯한 숫자를 쓴다 → 눈에 띄지 않는다
```

**VLM 의 위험은 못 읽는 것이 아니라 그럴듯하게 지어내는 것입니다.**
깨진 결과는 걸러낼 수 있지만 그럴듯한 오답은 그대로 통과합니다.

---

## 어떻게 잡는가

```
이미지
  ├─ 모델 A (상용 폐쇄 가중치)  ┐
  └─ 모델 B (오픈소스 가중치)   ┘  ★ 벤더·계열이 달라야 같은 실수를 하지 않는다
       ↓
  필드 대조          두 모델이 갈리는 자리 = 못 믿을 자리
       ↓
  코드 검산          LLM 호출 없이, 답이 스스로를 검산한다
       ↓
  판정               자동 처리  /  사람에게
```

**LLM 과 코드의 역할을 나눕니다.** 모델은 읽기만 하고, 계산과 판정은 코드가 합니다.
산수를 모델에게 맡기면 틀릴 뿐 아니라 **어디서 틀렸는지 알 수 없게 됩니다.**

### 검산의 예 — 영양성분표

숫자를 완벽히 읽어도 **기준량**을 놓치면 결과가 통째로 틀립니다.

```
제품 A   "100g당"             단백질 12g   총 내용량 250g   →  실제 30g
제품 B   "1회 제공량(30g)당"   단백질 12g   총 3회 제공      →  실제 36g
```

같은 `12g` 인데 실제 섭취량이 3배까지 갈립니다. 표 밖 구석에 작게 적힌 "1회 제공량 30g" 을
VLM 이 자주 놓치는 자리입니다.

| | 검산 | 무엇을 잡나 |
|---|---|---|
| ① | 칼로리 ≈ 탄수×4 + 단백×4 + 지방×9 | 숫자 오독 |
| ② | 1회 제공량 × 제공 횟수 = 총 내용량 | **기준량 오독** — ①이 맞아도 이게 틀리면 배수로 틀린다 |
| ③ | 당류 ≤ 탄수화물 · 포화지방 ≤ 지방 | 부분이 전체를 넘을 수 없다 |
| ④ | 나트륨 mg · 탄단지 g | 단위 혼재 |

## 쓰지 않는 것

| | 이유 |
|---|---|
| 벡터DB · 임베딩 | 한 장에서 정해진 값을 뽑는 것은 **검색이 아니라 추출**입니다 |
| LLM 에게 산수 | 코드가 정확하고 검증 가능합니다 |
| LLM 에게 최종 판정 | 판정까지 모델이면 무엇을 믿을지 알 수 없습니다 |

검색이 필요한 요구사항이 생기면 그때 Retrieval 계층을 따로 얹는 것이 맞다고 봅니다.
RAG 는 별도 저장소([md-rag-chatbot](https://github.com/songwookun/md-rag-chatbot))에서 다뤘습니다.

### 아직 답하지 못한 것

> **"두 모델이 다르면 틀린 것이다" 라는 전제가 참인가?**

설계 전체가 이 전제 위에 서 있는데 **아직 재지 않았습니다.**

```
                  실제로 맞음      실제로 틀림
두 모델 일치        자동처리         못 잡는다  ← 이 비율이 설계의 상한
두 모델 불일치      헛경보           잡았다
```

우상단이 크면 교차검증만으로는 부족하고 검산이 더 중요해집니다.
`notebooks/01_baseline.ipynb` 의 Phase 2 가 이 질문에 답합니다.

## 실행

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env      # 키 두 개를 채웁니다
```

| 키 | 무료 티어 | 발급 |
|---|---|---|
| `GEMINI_API_KEY` | 있음 | https://aistudio.google.com/apikey |
| `GROQ_API_KEY` | 있음 | https://console.groq.com/keys |

실험 노트북을 돌리려면 `pip install -e ".[dev,lab]"` 입니다.
